C4 (.cf sources, .ch headers) looks like C++ but is not, and C++ habits are its usual compile errors. Read the c4-language skill before writing C4, c4-testing before writing tests. What every program needs:
- One program per project: all .cf/.ch files of src/ compile together. `include "x.ch"` (no #include, no ../). File-scope names (constants, static helpers) share one scope per namespace across ALL files: two files may not both define `kMax` or `static Parse`.
- Entry: `int32 main(int32 argc, char** argv)`. Types: int32, int64, uint8, float, double, bool, char8. No `auto`: write the type. Arrays and pointers belong to the type: `int32[4] a;`, not `int a[4]`.
- Class members are private unless marked, each one: `public int64 count;`. Constructors, destructors and operators are annotated methods: `[operator("create")] public void Init(int64 n) { ... }`, `[operator("delete")]`, `[operator("==")]`. Make objects with `T x = T(args);` or `T x(args);`; `new T(args)` is garbage collected. A lambda that returns a value names its type: `[](int32 x) -> bool { return x > 0; }`.
- Library: `include "bedrock.ch"`; there is no std::. Core::String (made explicitly: `Core::String("text")`; `s == "text"` works), Core::StringView, Core::StringBuilder, Core::Array<T> (Push, Count, Sort, SortBy), Core::HashMap<K, V> (Find, Insert, m[k]), Core::ParseInt64, FS::File, Platform::WriteOutput / WriteError (a StringView). Counts are int64. printf and Core::Format take C strings: pass `s.CStr()`, never a Core::String. There is no standard-input API.
- Before using a Bedrock type or function, read its exact signatures in the API digest: `docs_read({"path": "c4/library/bedrock-api.md", "heading": "Core::HashMap"})`; docs_search finds a function by name (`docs_search({"query": "ParseInt64"})`). Never guess C++ names (Push, not push_back; Count, not size), and do not read the toolchain's headers through the shell.
- Tests: `[test("group.name")] static void F() { assert_eq((int64)2, Count(), "why"); }` in src/tests/*.cf. Build and test with build_run (task "test"); try the built program with program_run: `build/bin/Development-windows-x64/<project>/<project>.exe`.
