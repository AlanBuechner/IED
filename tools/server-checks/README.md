# server-checks - what only the real server does

Black-box checks of an `ied-server` executable beyond the shared protocol suite (`tools/conformance`, which the mock
passes too): its access rules (`docs/11` "Access defaults", "Authentication on the wire") and file watching.
Each test starts its own server with `--test-hooks` and a data folder of its own, so they cannot leak state into each
other. Stdlib only; it reuses `tools/pylib/ws.py` and the conformance client for protocol calls.

```bat
python -I tools/server-checks/run_server_checks.py --server build\bin\Development-windows-x64\ied-server\ied-server.exe --cli build\bin\Development-windows-x64\ied\ied.exe --desktop build\bin\Development-windows-x64\ied-desktop\ied-desktop.exe
python -I tools/server-checks/run_server_checks.py --server <exe> -k lock -v
nuke conformance
```

| Module | Checks |
|---|---|
| `test_access.py` | a foreign Host refused on every path; loopback names accepted; `/healthz` open and terse; `/ws` without a session refused before the upgrade (401); `/api/*` 401 JSON; a page gets the login page (401) with the content policy, `nosniff` and `no-referrer`; only the login page's files are public; a foreign Origin refused on `/ws` (even with a session) and on auth POSTs; forged, other-port and empty cookies are no session |
| `test_tokens.py` | the `OPEN` line's 64-digit token; the exchange's 303 without the token and the cookie's attributes; a token works once; a token dies after its time (`testhooks.mintToken`); malformed tokens; the cookie opens a protocol session (`auth.devices`); `/api/auth/state`; neither `auth/devices.json` nor the log holds the cookie |
| `test_password.py` | login without a password (409); malformed logins (400); passwords have 12 characters; set then log in, devices listed, a wrong password gets no cookie; changing it needs the current one; five failures lock the address out, even for the right password, with `Retry-After`; the audit log's events in order and without secrets; `owner.json` holds an Argon2id string |
| `test_watching.py` | outside changes reach the client (created, changed, deleted, renamed); an outside write moves the revision so a stale `fs.write` conflicts; the server's own write, mkdir, rename and delete are each reported once; a clean open document reloads (origin `disk`), a dirty one gets `doc.diskChanged`, and revision 0 when its file is deleted; `.git/` is quiet; 300 files arrive in a few batches; created-then-deleted within a batch is nothing |
| `test_control.py` | one server per control pipe (a second exits 3); `status`; `url` signs in once; `open` of a file opens its folder once (any case), publishes `workspace.opened` and ends in `#open=`; JSON-RPC errors; `stop` says bye and ends the process; `logs/server.log` holds the run (start, listening, the stop, the exit; a refused start's reason) and `testhooks.crash`'s report (the thread's name, the line that threw); a relaunch (`testhooks.relaunch`) shows in `status` after its grace, the app's `relaunch.claim` takes it and the server then starts nothing, and one nobody claims stops the server and starts it again on its port with its workspace (`--relaunched` in its log). With `--cli`: `ied status` / `url` / `open --no-browser`, "no server runs", usage, and starting a server when none runs (under its own `LOCALAPPDATA`) then stopping it |
| `test_browser.py` | (Edge or Chrome installed; skipped without) a page's title, console and failed requests on `page:<pageId>`; frames pulled with `browser.frame` and mouse, keys and text forwarded; the AI's bindings (an accessibility snapshot with refs, type and click by ref, the `action` event with the element's box, eval, a screenshot PNG in the workspace, console and failed requests, a stale ref refused); only http(s) and the workspace's files open; pages kept across a restart and loaded again when looked at; closing; the browser tools in a chat turn against the fake model, the screenshot reaching a model that sees images |
| `test_desktop.py` | (with `--desktop` and `--cli`; the app's window shows) `ied-desktop` with no server running starts one under its own app-data folders, and its window signs in and shows the folder it was given; a server killed while the window is open is started again and the page reconnects, and `desktop.log` says each server, its exit code and its return; the page's relaunch, and one the server asks for (`testhooks.relaunch` on a check's server on the app's pipe: the watch claims it, the app relaunches itself and starts its own server with the window's folder); the app and its server are stopped however a check ends |
| `test_plugins.py` | declarative built-ins load and contribute; broken manifests fail with their reasons (schema pointer, API range, js kind, a builtin outside the install, not JSON), folders without a manifest are not plugins; an app plugin needs approval of its exact content and again after a change; an approved app plugin overrides the built-in of its id; disabling survives a restart; dependencies (in range, too old, missing, optional, on a failed plugin, cycles); plugin files served only from inside a loaded plugin, to a session |
| `test_trust.py` | a folder opens untrusted; trusting it is kept in app data across restarts (nothing written into the folder), and so is taking it back; both go to the security log |
| `test_settings.py` | the catalog from a plugin's schema (tiers, merge, page); defaults and the app file's values; `settings.set` keeping a file's comments, the solution tier winning, objects merged and lists appended, reset falling back; refusals (unknown key, a tier the key does not allow, a value its schema refuses with the problems, a stale revision, an unknown tier); hand edits live with problems on their lines and the last valid value kept; settings gone with their plugin and back; an app plugin appearing without a restart |
| `test_solutions.py` | a solution opened with its projects (a glob and a path), roots resolved, items; a new project under the glob and a removed one reported live with their problems (schema pointer, missing root, missing file); the project tier winning for its project only; local plugins untrusted until the workspace is trusted, then contributing and bringing their settings to that workspace alone; a local plugin with the wrong id failing; a solution opened over the control pipe once |
| `test_outputs.py` | every workspace's `ied` source (the server log, with what was logged before it opened and each line's time); a broken solution's problems arriving as `append` events; `out.clear` |
| `test_language_servers.py` | (with `fake_lsp.py`) a served document starts its server, nothing before; `didOpen` with text, version and language id; diagnostics on `diag:<wsId>` in UTF-16 from a UTF-8 server; edits become full-text `didChange`, saves `didSave`; `lsp.request` adds the document, converts positions both ways and maps `file:` URIs of the workspace to `ied://`; `lsp.capabilities`; an unserved document (`not_found`, `{profile: null}`); a server that exits fails its request, starts again and gets its documents again; `lsp.restart` (shutdown first, a new process); the server's stderr in the `ied` output |
| `test_file_operations.py` | a renamed folder takes its files' revisions and the documents open in it (same docId, unsaved edit kept, saved at the new path, `doc.renamed`); a folder cannot move into itself or onto a file; a renamed file takes its document; a folder is deleted only with `recursive`, and documents open in it get `doc.diskChanged` revision 0; the workspace folder itself cannot be renamed; deletes go to the trash (`trash.list` newest first with sizes, `trash.restore` puts a folder back with its contents and refuses when something is there, `trash.purge`; an id never names a path outside the trash) |
| `test_devices.py` | `auth.revoke` sends `bye auth-revoked`, closes the device's sockets (1008) and kills its cookie; logout clears the cookie and the session; device sessions survive a restart on the same port; a corrupt devices file stops the server; a non-loopback `--host` is refused until a password exists |
