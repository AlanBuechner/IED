# server-checks - what only the real server does

Black-box checks of an `ied-server` executable beyond the shared protocol suite (`tools/conformance`, which the mock
passes too): its access rules (`docs/11` "Access defaults", "Authentication on the wire") and file watching.
Each test starts its own server with `--test-hooks` and a data folder of its own, so they cannot leak state into each
other. Stdlib only; it reuses `tools/pylib/ws.py` and the conformance client for protocol calls.

```bat
python -I tools/server-checks/run_server_checks.py --server build\bin\Development-windows-x64\ied-server\ied-server.exe --cli build\bin\Development-windows-x64\ied\ied.exe --desktop build\bin\Development-windows-x64\ied-desktop\ied-desktop.exe
python -I tools/server-checks/run_server_checks.py --server <exe> -k lock -v
nuke conformance
```

Each check starts the master (`docs/01` "Processes"); its workspaces run in workspace servers it starts. `routed.py`'s
`RoutedClient` keeps a tab's sockets as the web client does - the master's and one per workspace server through
`/w/<wsId>/ws` - and sends each request and subscription where the master's routes say (`docs/10` "Routing"), so a check
talks to "the server" as before.
