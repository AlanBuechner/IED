## Policy notes
- **Build:** `nuke build` from the repository root (the folder above C4; Development, and it refreshes the `dev` toolchain), or Frost directly: `cmd /c "Build.bat -b -c Development -a x64 -p <C4 root>"` (from the C4 root; `Build.bat` passes its arguments to `Frost/Build.py`). Dependencies (LLVM, Python, submodules) come from `setup.bat` at the repository root. Plain `-b` does NOT reliably recompile after file deletion/stash (stale-binary trap) - use `-rebuild` for a consistent binary. **CRITICAL TRAP: Frost SILENTLY SWALLOWS clang-format compile errors** and still prints "error code 0" / exit 0, leaving a stale binary that looks green. ALWAYS grep the full log for `: error|error C\d|fatal error`. Verify a changed .cpp actually recompiled (its `.obj` newer than the source) before trusting any probe result. C4Testing is a unit-test project: plain `-b` NEVER rebuilds it; use `nuke test` (repository root) or `python Frost/Build.py -test -c Development -a x64 -p <C4 root>` (runs C4Testing, CoreTesting and ReflectionTesting; its exit code is the gate - when its output is redirected the suites' lines may not show, so also run `bin/Development-windows-x64/C4Testing/C4Testing.exe` directly for the per-test list). A root build also builds CBind, C4DAP and C4Script (`toolPaths`).
- **CRITICAL TRAP (orphan objects): Frost links EVERY `.obj` in `bin-int/<Config>-windows-x64/<Module>/`, so orphan .obj files whose source was deleted/renamed are silently linked and OVERRIDE fresh code.** After any rename/delete, purge every .obj with no matching current .cpp under `<Module>/src`. See skill `c4/c4-build-stale-obj-trap`.
- **Gates after every change:** `nuke gates` from the repository root builds, then runs every one of these (steps in `nuke.toml`): C4Testing (`python Frost/Build.py -test ...`), e2e `assets/TestCode/RunTests.ps1` (-O0 AND -O2), negative `assets/NegativeTest/RunTests.ps1` (-O0 and -O2), IsolatedTest runner, Bedrock standalone (`C4.exe Bedrock\Tests -test`). Also IsolatedTest at `-O2`, RuntimeTest, ScriptTest (`assets/ScriptTest/RunTests.ps1`, -O0 and -O2) and ToolsTest. The full list is section 2 of the plan.
- **Git worktrees:** `Frost/vendor/` and the repository root's `vendor/` are not committed, so a new worktree has neither: run `setup.bat` in it. It initializes the submodules (Frost's yaml-cpp and tracy), installs the small packages, and makes `Frost/vendor/Compiler` a junction to the main checkout's LLVM instead of a second 4 GB copy (remove a junction with `cmd /c rmdir`, never a recursive delete, before the worktree goes). A clean tree builds with plain `-b` (`nuke build`): early projects build after the ones they link (verified 2026-10-20 on an empty tree).
- **Test hygiene:** NOTHING test-related in the repo root. All test sources/logs/scratch under `assets/`; runner scratch to `assets/build-output/<suite>/`.
- **ASCII-only** in source and docs (no em-dashes/curly quotes/arrows). Non-ASCII bytes in a diff = corruption to repair. **PowerShell `Set-Content -Encoding utf8` PREPENDS A BOM** - strip the leading 3 bytes if 239,187,191 and verify no byte > 127.
- **Bedrock namespaces (D-58):** one level deep - `Core`, `FS`, `Serialization`, `Reflection`, `GC`, `Threading`, `Platform`, and `Math` for the opt-in math library (`include "math.ch"`, D-46). Namespaces are open (C++-style), so a program may add members to any of them.
- **Toolchains:** C4 workspaces build with a toolchain from `<repository root>/toolchains/c4/`. `dev` is refreshed by every Development `nuke build` from the repository root (a direct Frost build does not); a numbered version comes from `nuke install-c4` and never changes (bump `C4Lib/src/Compiler/Version.h` first). After meaningful changes verify the workspaces' `nuke build` stays warning-free.
- **NEVER kill the language server with `-match 'C4'`** (it matches C4LSP). Use `Get-Process -Name C4` exactly, or move the locked exe aside.
- **Frost gotchas:** plain `Build.py` without `-b/-rebuild/-fb` silently no-ops; content-hash freshness means revert+restore to identical content does NOT recompile (verify exe mtime > changed .obj mtime after any A/B). Frost source discovery is RECURSIVE - subfolders like `Model/Types/` are build-safe.
- **AGENTS.md standards:** minimal comments; honest functions; no global mutable state; one level of abstraction per function; single purpose; no bloated files (1:1 .h/.cpp, <= ~600 lines); tests with real coverage; delete dead code; no speculative abstractions.
